# Детекторы российских персональных данных

Документ описывает доработку расширения Offsend: поиск и маскирование российских
персональных данных — телефонов, почтовых адресов, паспортов, СНИЛС, банковских
счетов и карт «МИР». Исходный проект: [offsend/browser-extension](https://github.com/offsend/browser-extension)
(Apache-2.0).

## 1. Что добавлено

| Тип (`FindingType`) | Детектор | Примеры | Как отсекаются ложные срабатывания |
|---|---|---|---|
| `phone` | `phone-e164` | `+7 (999) 123-45-67`, `89991234567`, `8-800-555-35-35`, `8 (3452) 12-34-56`, `доб. 102` | 4 строгие формы записи; 11 цифр подряд — только 9xx и 800; 7 цифр — только после «тел.» |
| `address_ru` | `address-ru` | `101000, г. Москва, ул. Мясницкая, д. 26, кв. 5`, `мкр. Северный, д. 5` | адрес принимается, только если есть номер дома; индекс — только из справочника |
| `passport` | `passport-ru` | `паспорт 4512 123456`, `серия 4512 № 123456`, `45 12 123456` | год бланка в серии (97–99, 00…текущий+1); без слова «паспорт» — только `45 12 123456` |
| `snils` | `snils` | `112-233-445 95`, `СНИЛС 11223344595` | контрольное число; 11 цифр подряд — только после «СНИЛС» |
| `bank_account` | `bank-account-ru` | `р/с 40702810938000012345`, `40817 810 5 7000 0123456` | со словом «р/с»/«счёт» — любой счёт, кроме корсчёта 301…; без слова — только счета физлиц (40817, 40820, 40802, 423, 426) с известным кодом валюты |
| `credit_card` | `credit-card` (доработан) | `2200 7001 2345 6781` (МИР), Visa, Mastercard | алгоритм Луна **и** префикс платёжной системы |

Все новые типы включены по умолчанию и выводятся переключателями в разделе
«Детекторы» настроек. Подстановки при маскировании: `{{ADDRESS_RU_1_…}}`,
`{{PASSPORT_1_…}}`, `{{SNILS_1_…}}`, `{{BANK_ACCOUNT_1_…}}`.

ИНН и БИК по решению преподавателя не детектируются. Цифры ИНН из чеков
по-прежнему не должны распознаваться как телефон или паспорт (это закреплено тестами).

## 2. Адреса

Код: `src/core/detection/ru-address.ts`.

Адрес ищется в два шага.

1. **Компоненты.** Отдельными регулярными выражениями ищутся: почтовый индекс,
   регион, район/округ, населённый пункт, улица, элемент планировочной структуры
   (микрорайон, квартал, территория, СНТ), дом (с корпусом, строением, литерой),
   квартира/офис. Ключевые слова поддерживаются и перед названием (`ул. Тверская`),
   и после него (`Тверская ул.`, `Московская обл.`, `3-й мкр.`).
2. **Склейка.** Компоненты, стоящие подряд через запятую, пробел или перенос
   строки, объединяются в цепочку (динамическое программирование: для каждого
   компонента запоминается самая длинная цепочка, которая с него начинается).
   Цепочка считается адресом, если в ней есть **номер дома** и хотя бы **улица,
   микрорайон или населённый пункт**.

Поэтому `г. Москва, ул. Тверская, д. 1` маскируется одним блоком, а `г. Кострома`,
`Улица Ленина очень длинная` или `мкр. Северный строится` — не маскируются.

**Словарь сокращений** построен по Правилам сокращённого наименования
адресообразующих элементов (приказ Минфина России от 05.11.2015 № 171н) и дополнен
бытовыми вариантами: `ул.`, `пр-кт`/`просп.`, `пер.`, `б-р`, `ш.`, `пр-д`, `наб.`,
`пл.`, `мкр.`/`мкр-н`/`микрорайон`, `кв-л`, `тер.`, `г.о.`, `м.р-н`, `р-н`, `обл.`,
`респ.`, `г.`, `п.`/`пос.`, `пгт`, `с.`, `д.`, `ст-ца`, `х.`, `д.`/`дом`, `корп.`/`к.`,
`стр.`, `лит.`, `уч.`, `кв.`, `оф.`, `пом.`, `ком.`.

Однобуквенные сокращения (`п.`, `с.`, `д.`, `х.`) принимаются только с точкой и
с названием с заглавной буквы: «с Иваном» — предлог, а не село; «д. 5» — дом, а
«д. Ивановка» — деревня. «г.» без точки допускается (`г Москва` — так пишет ФИАС).

**Почтовые индексы** проверяются по словарю: `src/core/detection/postal-index.ts`.

- Источник — эталонный справочник почтовых индексов ФГУП «Почта России», выгрузка
  [sanmai/pindx](https://github.com/sanmai/pindx) (Apache-2.0), данные от 2026-10-05,
  61 317 индексов.
- В коде индексы хранятся сжатыми сериями (~57 КБ текста), при первом обращении
  разворачиваются в битовую карту на 900 000 значений (~110 КБ памяти), проверка —
  одна операция над байтом.
- Обновление словаря: `git clone --depth 1 https://github.com/sanmai/pindx /tmp/pindx`,
  затем `npm run postal-index -- /tmp/pindx`.
- Шестизначное число, которого нет в справочнике (`Заказ 123456, ул. Ленина, д. 5`),
  в адрес не включается.

## 3. Документы и реквизиты

Код: `src/core/detection/ru-documents.ts`.

**СНИЛС.** Первые 9 цифр умножаются на веса 9, 8, …, 1 и складываются. Сумма меньше
100 — это контрольное число; 100 и 101 дают `00`; больше 101 — остаток от деления на
101 (результат 100 снова даёт `00`). Номера не больше 001-001-998 не принимаются: для
них контрольное число не определено.

**Паспорт РФ.** Серия — 4 цифры (2 — код региона, 2 — год изготовления бланка), номер —
6 цифр. Контрольной суммы нет, поэтому используются: год бланка (бланки нового образца
выпускаются с 1997 года) и контекст — слова «паспорт», «серия» перед номером.

**Банковский счёт.** 20 цифр: 1–5 — балансовый счёт, 6–8 — код валюты. Контрольный
ключ рассчитывается вместе с БИК, а БИК исключён из задания, поэтому решение
принимается по слову-подсказке рядом и по номеру балансового счёта.

**Карты.** К алгоритму Луна добавлена проверка префикса и длины номера: МИР
(2200–2204), Visa (4), Mastercard (51–55, 2221–2720), American Express, UnionPay, JCB,
Discover, Diners, Maestro. Случайное число проходит алгоритм Луна в 10% случаев;
префикс отсекает большую часть таких совпадений.

## 4. Изменения движка

Код: `src/core/detection/ts-engine.ts`, `detectors.ts`.

- **Детектор с методом `find(text)`.** Адресу и счёту одной регулярки мало: адрес
  собирается из нескольких фрагментов, счёт принимается по слову рядом. Такие
  детекторы сами обходят текст; обычные по-прежнему задаются `pattern()`.
- **Лимит времени (50 мс) больше не отключает встроенные детекторы.** Раньше на
  длинном тексте или медленной странице детекторы в конце списка (телефоны, адреса)
  молча пропускались — пользователь видел «ничего не найдено». Теперь лимит действует
  только на пользовательские правила и Smart PII.
- **Лимит совпадений** считает только прошедшие проверку значения (раньше мусорные
  кандидаты — даты в логе — вытесняли настоящие номера). Для встроенных детекторов
  лимит поднят с 200 до 5000.
- **Разрешение пересечений** — двоичный поиск по отсортированному списку вместо
  перебора всех принятых находок (было O(n²)).
- **Проверки контекста назад** (`СНИЛС`, `паспорт`) выполняются только в начале
  числа (`(?=\d)` перед проверкой): на прозе это ускорило скан в 10 раз.

**Текст из Word, с сайтов и из PDF** (`src/core/detection/normalize.ts`). Вместо
обычных символов в таком тексте стоят «двойники»: неразрывный пробел (Word ставит
его в номерах), неразрывный дефис, тире, минус, символы нулевой ширины,
полноширинные цифры. Внешне разницы нет, а регулярки их не ждали — значение
уходило без маски. Движок ищет в нормализованной копии текста (двойники заменены
обычными символами, невидимые удалены), а найденные позиции переводит обратно в
исходный текст: маска и Restore работают с тем, что набрал пользователь.

**Повторы значения.** Часть детекторов решает по контексту («123-45-67» — телефон
только после «тел.», 11 цифр — СНИЛС только после «СНИЛС»). Если значение найдено
хотя бы один раз, движок маскирует и все его точные повторы в тексте. Без этого
повтор оставался открытым, а проверка перед отправкой (`isMaskCommitted`) не
находила подтверждения маскирования, и сообщение не уходило вовсе.

**Склеенный текст.** При вставке списка в поле ввода, которое теряет переносы
строк (так ведёт себя, например, Gemini), строки слипаются: к значению прилипают
слова и цифры соседних строк, а номера — друг к другу. Исходно все детекторы
требовали «не буква и не цифра» по краям, и такие значения уходили без маски, а
британский номер с прилипшей цифрой следующей строки (`+44 20 7946 09152`)
становился «картой». Что сделано:

- у цифровых детекторов (телефон, СНИЛС, паспорт, счёт, карта, IP) по краям
  запрещены только цифры, буквы вплотную допускаются;
- чтобы не ловить цифры в хешах и ID, значение отбрасывается, если с обеих сторон
  к нему вплотную латинская буква или «_» (`a3f89991234567bc…`): при склейке
  слово прилипает только с одной стороны;
- телефон с `+7` — ровно 11 цифр; отрезки, где подряд слиплись несколько номеров
  (`8999123456789167778899`, `+7 (999) 123-45-678-800-555-35-35…`), режутся на
  номера целиком, без остатка — иначе отрезок не принимается (штрихкод, ИНН);
- у адресов компонент может стоять вплотную к цифре или начинаться с заглавной
  сразу после строчной (стык строк), а после номера дома допускается слово.

Порядок детекторов важен: при пересечении побеждает тот, что выше в списке.
СНИЛС, паспорт и счёт стоят раньше карт и телефона, адрес — раньше телефона.

## 6. Известные ограничения

- Город без «г.» распознаётся только из короткого списка (Москва, Санкт-Петербург,
  Севастополь, Россия/РФ) или сразу после индекса. В `Екатеринбург, ул. Малышева 51`
  замаскируется только `ул. Малышева 51`. Расширить список до всех городов — следующий
  шаг (можно взять названия из того же справочника индексов).
- Адрес без номера дома не маскируется намеренно — так требует задание.
- Названия улиц, написанные со строчной буквы (`ул. ленина`), не распознаются.
- 11 цифр подряд с городским кодом (`84951234567`) не считаются телефоном.
- В склеенном тексте прилипшая цифра соседней строки может попасть под маску вместе
  со значением (`+44 20 7946 09152`, `192.168.1.146`): где кончалось значение,
  неизвестно, поэтому маска берёт самый длинный допустимый вариант.
- Номер с прилипшим словом только с одной стороны (`order_89991234567`) находится:
  отличить его от склейки строк нельзя.
- Склеенные строки с IP-подобной версией (`2.5.10.2024`) дают IP `2.5.10.202`.
- Номер, разорванный переносом строки (`8 (999)` / `123-45-67`), не находится:
  разрешить перенос внутри номера — значит склеивать числа соседних строк таблиц.
- Номера разделов из четырёх чисел (`п. 7.1.2.3`) по-прежнему считаются IP.
- Паспорт без слова «паспорт» и не в виде `45 12 123456` не распознаётся.
- Контрольный ключ банковского счёта не проверяется (нужен БИК).
- Вложение размером 2 МБ сканируется около 1,7 с; больше 5000 находок одного типа в
  одном тексте не маскируются.

## 7. Публикация

- Доработанная версия выпускается под собственным названием «Чёрный заслон»: карточка Offsend в
  магазинах принадлежит авторам исходного проекта. Заменены название в
  `public/_locales/*/messages.json`, иконка `src/assets/icon.png`, идентификатор для Firefox и
  `homepage_url` в `wxt.config.ts`.
- Лицензия Apache-2.0: файл `LICENSE` сохранён, в изменённых файлах есть пометка об изменении,
  список изменений и указание исходного проекта — в `NOTICE`.
- Телеметрия отправляется только если при сборке задан `WXT_TELEMETRY_APP_ID`; без него сборка
  ничего не отправляет.
- Архивы: `npm run zip:all`. Релиз на GitHub собирается автоматически при отправке тега вида
  `v0.4.0` (`.github/workflows/release.yml`).
